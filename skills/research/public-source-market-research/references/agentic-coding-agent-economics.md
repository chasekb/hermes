# Agentic Coding Agent Economics — Evidence Bank

This note captures the live-source findings from the July 2026 research pass on "openclaw-type" agentic coding tools.

## Scope note
Assumption used in the session: "openclaw-type agents" refers to agentic coding CLIs / workflows such as OpenCode, Claude Code, and Codex.

## Primary-source evidence snapshots

### Claude Code
- Anthropic product page states Claude Code is included in Pro and Max plans.
- The same page states Claude Code works on macOS, Linux, and Windows.
- Claude Code docs state it consumes API tokens at standard API pricing when used with a Claude Console account.
- Claude Code cost docs state subscription users see usage included in the plan, while console users are token-billed.

### Codex
- OpenAI Codex pricing page states Codex is included in ChatGPT Free, Go, Plus, Pro, Business, Edu, and Enterprise plans.
- The pricing page shows at least three consumer price points that matter for adoption framing: Free ($0/mo), Go ($8/mo), and Plus ($20/mo).
- The docs position Codex for quick/light coding tasks, CLI use, and cloud-integrated review workflows.

### OpenCode
- OpenCode homepage describes it as an open source AI coding agent.
- The homepage states free models are included or users can connect any model from any provider.
- The CLI/docs position it as a provider-agnostic orchestration layer for terminal, IDE, or desktop use.

## Economics interpretation used in the report
- The best monetization usually comes from selling a service outcome, not from trying to sell the agent itself.
- The strongest workflow classes are bounded, repeatable, and easy to verify.
- Human review still matters for anything revenue-critical or security-sensitive.

## Opportunity ranking used in the report
1. Maintenance retainers for SMB SaaS / internal tools
2. Test and CI hardening packages
3. Migration and upgrade services
4. Integration / glue-code agency work
5. Internal developer productivity tooling
6. Content / SEO / idea-to-app automation

## Research prompt pattern that worked
- Separate product-state, monetization, workflow automation, and risk into distinct questions.
- Use live docs and pricing pages as the anchor evidence.
- State assumptions explicitly when the category name is ambiguous.
- Rank by willingness to pay, repeatability, verification burden, and margin after tool costs.
