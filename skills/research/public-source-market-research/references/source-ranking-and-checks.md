# Source Ranking and Checks

This reference captures the practical source-selection rules for current-state market research.

## Best source types
- Official product or pricing pages for what is currently offered.
- Official company newsrooms for launches, partner programs, and pricing changes.
- GitHub API / repo metadata for stars, forks, creation dates, and update timestamps.
- npm/PyPI/registry APIs for package activity and release recency.
- Public partner/service pages for monetization patterns and service offerings.
- Public consulting pages for price points and engagement models.

## Claim checks
- Date the claim: if the page is live, quote the publication date and the retrieval date.
- Separate **listed pricing** from **actual revenue**.
- Separate **self-reported scale** from independently verifiable telemetry.
- When possible, corroborate one claim with a second source of a different type.

## Good bullet format
- Claim, then why it matters, then source URL, then date.
- Keep one claim per bullet.
- Put unsupported inference in a separate bullet labeled inference.

## Practical examples of useful telemetry
- GitHub stars and repo creation/update timestamps.
- npm downloads over last week/month.
- Public certification counts or partner counts.
- Public pricing tiers and subscription pages.
- Publicly advertised hourly rates or service retainers.

## Common failure modes
- Search-result snippets used as evidence instead of the underlying page.
- Agency pages treated as market-wide facts.
- Old blog posts used for current pricing.
- “AI revenue” claims without a direct source or a dated announcement.
